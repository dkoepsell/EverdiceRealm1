Why Discord is the right integration point

Most online tabletop play already happens on Discord:

Voice + text in one place

Persistent channels per campaign

Dice bots, music bots, initiative bots are already normalized

Players expect Discord as the “table,” not the VTT

Everdice doesn’t need to replace Discord. It should act as the game engine and campaign brain behind it.

Think of it as:

Discord = the table
Everdice = the DM’s notebook + rules brain

The correct architectural model (important)
❌ What not to do

Do not try to:

Host voice

Rebuild chat

Compete with Discord’s UI

Turn Everdice into a Discord clone

That’s expensive, fragile, and unnecessary.

✅ What does work (clean + scalable)
1. Everdice Discord Bot (thin, controlled)

Create an Everdice Bot that:

Lives in a server

Responds to slash commands

Acts as a bridge to Everdice’s backend API

Examples:

/everdice start-session
/everdice roll 1d20+5
/everdice npc "Captain Varra"
/everdice scene next
/everdice recap


The bot:

Sends commands to Everdice

Receives structured responses

Posts clean summaries back into Discord

2. Session-linked Discord channels

Each Everdice campaign maps to:

One Discord server (or category)

One or more text channels:

#session-log

#dice-rolls

#gm-notes (private)

#recaps

Everdice:

Knows which Discord channel = which campaign/session

Posts session summaries, roll outcomes, scene transitions

This matches how people already organize games.

3. Voice stays external (this is good)

Voice stays entirely in Discord:

Players talk normally

DM runs Everdice in browser or tablet

Bot posts outcomes, not chatter

This keeps latency low and expectations familiar.

How Everdice would actually be used in play
DM workflow (live session)

DM opens Everdice dashboard

Clicks “Start Session”

Discord bot posts:

🗡️ Session 12: The Clockwork Vault has begun.

During play:

DM triggers rolls, encounters, NPC states

Everdice resolves logic

Bot posts results

At the end:

DM clicks “End Session”

Everdice auto-generates recap

Bot posts it to #session-log

Players never leave Discord.

Player workflow

Players:

Join voice

Read bot outputs

Roll dice if allowed

Never touch Everdice unless invited

This massively lowers friction.

How this fits CAML (important for your system)

CAML is actually a huge advantage here.

Because CAML is structured:

Scenes

Events

Rolls

Outcomes

Consequences

You can serialize:

Every session

Every decision

Every roll

Which means:

Discord becomes a rendering layer

Everdice remains the canonical record

Sessions can be exported as:

Markdown

PDF

Replay logs

“Previously on…” summaries

This is exactly the kind of separation that makes Everdice feel serious rather than gimmicky.

MVP version (what I’d build first)

If you wanted to test this quickly, the MVP is:

Discord bot with:

/everdice link-campaign

/everdice roll

/everdice recap

Webhook-based posting (no real-time streaming needed)

One-directional trust:

Discord → Everdice (commands)

Everdice → Discord (summaries)

You could have this live with very little surface area.

Why this is good for adoption

This directly addresses your earlier concern about:

insecure or inexperienced DMs

Discord integration:

Makes Everdice feel familiar

Lets DMs hide complexity

Signals professionalism

Reduces “blank page” anxiety

It also fits perfectly with Reddit growth:

“Hey, we’re running a Discord-based campaign using Everdice.”

That’s immediately legible to D&D folks.

Bottom line

Yes, Everdice should integrate with Discord.
But:

As a session companion, not a platform replacement

Via a bot + API bridge, not voice or chat hosting

Using CAML as the authoritative game record
