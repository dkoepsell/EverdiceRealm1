1. Discord Bot Core (Required)
1.1 Bot Identity & Permissions

Discord application + bot user

OAuth2 invite flow with scoped permissions:

applications.commands

bot

Read/send messages

Embed links

Manage threads (optional but very useful)

Server-level installation (not per-user)

1.2 Slash Command Framework

All user interaction happens via /everdice …

Core commands

/everdice help

/everdice status

/everdice ping

Campaign commands

/everdice link-campaign

/everdice unlink-campaign

/everdice campaign-info

Session commands

/everdice start-session

/everdice pause-session

/everdice end-session

/everdice recap

2. Campaign & Session Mapping (Critical)
2.1 Discord ↔ Everdice Binding

Map:

Discord Server ID → Everdice Campaign ID

Discord Channel ID → Everdice Session ID

Persistent storage of bindings

One campaign per server (MVP)

Multiple channels per campaign (sessions, logs, dice)

2.2 Role & Permission Mapping

Identify DM role:

Discord role check (e.g. “Dungeon Master”)

Or Everdice campaign owner

Enforce command permissions:

DM-only commands

Player-allowed commands

Optional GM-only private channels

3. Slash Command Gameplay Features
3.1 Dice & Mechanics

/everdice roll <expression>

Supports 1d20+5, advantage, disadvantage

/everdice save <stat>

/everdice skill <skill>

/everdice initiative

/everdice damage <amount>

Output:

Clean, readable embeds

Clear attribution (“Rolled by Aria”)

3.2 Scene & Narrative Control (CAML-powered)

/everdice scene current

/everdice scene next

/everdice scene jump <scene-id>

/everdice event trigger <event-name>

Bot posts:

Scene title

Location

Active NPCs

Current stakes

3.3 NPC & World Interaction
